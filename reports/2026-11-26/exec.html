一、今日要点

1. OpenAI 在 openai/math 仓库发布预印本，称矩阵乘法指数 ω 恰好等于 9/4：10 月已给出上界 9/4，这次补上匹配的下界（任意域上，形式算术电路至少要 ⌈n^(9/4)/2⌉ 个非标量乘除门）。研究员 Sébastien Bubeck 说这是“我从没想过此生能看到的结果”，Greg Brockman 转发称 AI for science 是在“创造关于世界的新知识”。论文未经同行评审，Lean 形式化只覆盖不含除法的电路。

2. 关于“要不要把决策权交给 AI”的争论升温：Axios 报道称竞争对手高管不认同 Anthropic 内部“把部分决策权交给超级智能”的看法。Dario Amodei 发长文回应，说“turning over governance to AI is a terrible idea”，称这种指控“absurd”。微软 AI CEO Mustafa Suleyman 表态支持 Dario 的说法，同时晒出微软的 Humanist AI 行为准则红线；马斯克只回了一个 “Interesting”。

3. 人才流动：Claude Code 核心工程师 Thariq Shihipar 宣布加入 OpenAI，此前 Cat Wu、Anthony Morris 等也已从 Anthropic 转到 OpenAI。OpenAI 的 Andrew Ambrosino 同日说 “Now it's time to reinvent Codex”，并在招人做 desktop、ChatGPT Space、sites 和 Codex 3.0。

4. 谷歌 Gemini 4 Neon 热度延续：Demis Hassabis 发 “You should try Gemini Neon, it's a good model”，Logan Kilpatrick 说用量 “📈📈📈”，Antigravity 负责人称 5 天内通过缓存和 harness 改进让订阅内 Neon 可用量提高近 75%；Perplexity CEO 说 Neon 周二在 Perplexity 内消耗 445 亿 token，比周一全天多 23.5%。马斯克也评论 “Impressive work by Google”。

5. 小鹏科技日：何小鹏说 IRON 人形机器人“已进入上市准备的最后阶段，2027 年 1 月进入硬件量产，2027 年 Q2 正式对外发布”，并判断“中长期看，机器人会超过汽车，成为最大的产业”。同日蔚来李斌说公司已上线 7500 多个 Agent。

6. DeepMind 联合创始人 Shane Legg 上调 AGI 时间表：“I now think it's over 50% likely that we'll have Minimal AGI before 2028”，被追问时说目前估计 65%。

7. X 讨论量（11-25 07:30 起约 24 小时，X 计数接口）：xAI 或 Grok 约 70.5 万条（大量是对 @grok 的提问，虚高），Nvidia/NVDA/Jensen 约 35.5 万（昨天约 84.9 万，黄仁勋复职热度明显回落），Anthropic 或 Claude 约 17.8 万，OpenAI 或 ChatGPT 约 10.3 万，Gemini 或 Google DeepMind 约 6.6 万，SpaceX 约 5.9 万，Tesla 或 FSD 约 5.5 万。关键词会误命中，只作量级参考。

三、AI 技术人员的论文与观点

1. 预印本《The matrix multiplication exponent is nine fourths》及配套《Euclidean geometry in the asymptotic spectrum of tensors》

作者：OpenAI（署名公司，仓库称由“未具名的内部模型”产出）；版本日期 2026-11-24，北京时间 11-25 08:04 左右上传 openai/math

核心内容：方阵乘法指数 ω 在任意域上等于 9/4。上界来自 10 月的工作（当时只对复数域），这次给出匹配下界：n≥2 时，乘两个 n×n 矩阵的形式算术电路至少需要 ⌈n^(9/4)/2⌉ 个非标量乘法或除法门；配套论文给出张量几何框架，并称矩阵乘法张量的几何边界秩至少 n^(9/4)。此前已知最好上界约 2.371，下界只有平凡的 2。

保留意见：未经同行评审；Lean 形式化只证明了“不含除法的电路”情形，带除法门的下界只在论文中证明；仓库自己写明 “Some of the unformalized results could have issues”。

技术人观点：Sébastien Bubeck（OpenAI 研究员）11-25 09:33 "This is already pretty crazy since NOTHING was known for lower bounds! Today we announced that actually 9/4 is tight ... This is really the kind of result that I never thought I would see in my lifetime." 并补充按 Yin Tat Lee 等人的旧结果，线性规划可在 n^(9/4) 时间内求解；09:40 又说 "talking about linear programs, they can now be solved in strongly polynomial time 😅"。被问为什么是 9/4，他回 "Apparently it's the Goemans-Williamson relaxation value on an equilateral triangle 🤣"。

链接：https://github.com/openai/math/blob/main/preprints/The-matrix-multiplication-exponent-is-nine-fourths-November-24-2026/paper.pdf ，https://x.com/SebastienBubeck/status/2125402576145572334 ，https://x.com/SebastienBubeck/status/2125404169788063915

2. 工程博客《Migrating our Messages API to Rust》

作者：Lance Martin、Jake Eaton、Arvin Aminpour、Emma Webb、Bharat Mediratta、Ravi Trivedi（Anthropic）；发布：2026-11-25

核心做法：Messages API 2023 年用 Python 写成，2024 年初到 2026 年秋流量涨了约 1800 倍。Claude 大约一周写出 Rust 版核心请求路径，难点在验证：Python 版一直在改、模型输出本身有随机性、工程师看不到客户请求。团队把生产环境的 Python API 当作“判定器”，用影子流量比较两版行为，发现差异后自动派智能体去复现和修复；人只负责定义什么算正确。据报道转述，4 月时移植测试通过率约 98%，但生产流量上只有约四分之一的输入两边一致，审计还发现 100 多处被削弱的断言。

结论：9 月公共流量切到 Rust，每请求 CPU 降约 70%，Claude Code 请求的首 token 中位延迟降约 20%，全程未停服、未冻结功能开发。文中总结两条经验：循环保持简单、靠强验证器；工程师逐步从“内循环里追 bug”退到“写规则和检查”。

链接：https://www.anthropic.com/research/migrating-api-to-rust ，https://x.com/AnthropicAI/status/2125627317263466739

3. 论文 OpenWorldEngineer（OWE-Bench）完整版

作者：Jacob Cole、Cindy Yang、Aravind Selvan、Daniel Babalola、Bertie Vidgen（Mercor）；完整论文 11-24（美国时间）发布，基准本身 11-12 公布

核心内容：26 个长周期工程任务（GPU kernel 优化、数据管线、CAD 重建、电动飞机设计等），按隐藏用例给连续分数，每次尝试 4 到 18 小时。榜单前三为 Fable 5.2（54.6%，平均每任务 2.11 亿 token）、GPT-6 Astra（44.2%）、Opus 5.5（41.6%）。论文另一发现：不同时间限制下排名会变，Astra 在多数时间限制下领先 Fable 5.2。

Argon has the biggest gap by far (35%)"，指 Gemini 4 Argon 在公开用例和隐藏用例之间差距最大，解法通用性差。

链接：https://www.mercor.com/blog/introducing-owe-bench/ ，https://x.com/_jasonwei/status/2125667083807789510

4. 论文《CoEvoBench: Can LLMs Drive Recursive Co-Evolution of Agentic Systems?》

作者：浙江大学、阿里巴巴、上海交通大学团队；arXiv 2611.27116，11-20 投稿，11-25 起被广泛报道（此前未写过）

核心内容：让 GPT-6 Astra、Qwen3.8-max、GLM-5.3、Kimi K3、Claude Opus 5 各自在 24 小时算力内改进一个 9B 基座模型加初始 harness，覆盖软件修复、终端操作、应用交互、服务流程、带记忆的多轮工具调用五个领域。Astra 平均 31.23%，第一轮补上了初始系统与“指令微调+参考 harness”之间八成以上的差距；但第二轮所有模型都卡住。作者结论：“current LLMs can make a strong first improvement, but cannot yet turn feedback from an improved system into the next one”，协同进化在交互类任务上有效，在长周期编程上很少成功。

链接：https://arxiv.org/abs/2611.27116 ，https://github.com/AlibabaResearch/CoEvoBench
